# Оценка докладов конкурса (RWP-2026)

Мобильная веб-страница для членов конкурсной комиссии: эксперт открывает ссылку на телефоне, вводит фамилию и код комиссии и ставит баллы докладам по критериям. Оценки сохраняются в Google-таблицу через Google Apps Script. Аккаунты и пароли экспертам не нужны.

Конференция проходит 7 октября 2026 года (ПГТУ, Йошкар-Ола). Инструмент нужен в день конференции, поэтому приоритет у надёжности и простых правок, а не у новых функций.

## Файлы

- `index.html` — вся страница одним файлом: разметка, стили, JS. Без сборки, без зависимостей и без внешних CDN. Хостинг на GitHub Pages из корня ветки `main`.
- `Code.gs` — бэкенд на Google Apps Script. Код вставляется вручную в редактор Apps Script таблицы, в репозитории лежит как копия.
- `tests/smoke.py` — смоук-тест на Playwright в демо-режиме.
- `README.md` — краткое описание и порядок развёртывания (без кодов и URL `/exec`).

## Архитектура

```
Телефон эксперта (index.html на GitHub Pages)
   │  GET  ?action=ping|mine|all&code=…&juror=…
   │  POST JSON {action:"save", code, juror, id, title, scores[], total, status, comment, ts}
   ▼
Google Apps Script (веб-приложение, доступ «Все», выполняется от имени владельца)
   ▼
Google-таблица: лист «Оценки» (строка = эксперт × доклад), лист «Сводка» (формула QUERY)
```

- POST отправляется **без заголовка Content-Type** (по умолчанию text/plain), чтобы не было CORS-preflight: Apps Script не отвечает на OPTIONS. Не добавлять `headers: {"Content-Type": "application/json"}`.
- Apps Script отвечает редиректом на googleusercontent.com, `fetch` проходит его сам. Так задумано.
- В `doPost` есть upsert по паре (эксперт, ID доклада) и защита от устаревших правок по `ts`; запись идёт под `LockService`.
- Имя эксперта нормализуется (trim, схлопывание пробелов, lower-case, ё→е, «П.П.» = «П. П.») при поиске строки и в ключах localStorage. Функции `norm` в index.html и `norm_` в Code.gs должны совпадать.
- Роли определяются кодом: `ACCESS_CODE` — эксперт, `ADMIN_CODE` — администратор. `all` (оценки всех экспертов) доступен только администратору, остальные действия — обоим. `ping` и `mine` возвращают `role`.

## Клиент (index.html)

- Блок `CONFIG` в начале файла: `SCRIPT_URL` (ссылка `…/exec`; пустая строка = демо-режим, всё хранится только в localStorage), `SCALE_MAX`, `CRITERIA`, заголовки.
- `TALKS` — список 23 докладов из программы. ID имеют вид `s<секция>-<номер>`. Префикс `s` обязателен: иначе Google Sheets превратит `1-1` в дату.
- Секция 4 показывает порядковые номера вместо времени, потому что время в исходной программе сбито.
- Сохранение: каждое изменение ставит доклад в `pending` и сохраняет локально. Через 500 мс идёт `flush()`, при ошибке повтор каждые 8 с, а также при событиях `online` и `visibilitychange`. У каждого доклада есть статус «Сохраняю… / ✓ Сохранено / ⚠ Не отправлено».
- Ключи localStorage: `rwp_juror`, `rwp_code`, `rwp_role`, `rwp_filter` (выбранная секция), `rwp_data_<эксперт>`, `rwp_pending_<эксперт>`, `rwp_demo_all` (только демо).
- При уходе со страницы неотправленные оценки дополнительно уходят через `navigator.sendBeacon`; они остаются в `pending` и при следующем `flush()` отправляются ещё раз (повтор безопасен: upsert по `ts`).
- При входе выполняется `ping` для проверки кода. При старте выполняется `mine`: оценки эксперта подтягиваются с сервера, а локальные неотправленные правки имеют приоритет.
- Итоги: средний суммарный балл по экспертам. Учитываются только полностью заполненные оценки (все критерии) без статусов «не состоялся» и «воздерживается». Одинаковые средние получают одинаковое место.
- Администратор видит вкладку «Итоги» с режимами «Рейтинг» (общий), «Секции» (место внутри секции) и «Статистика» (сводка, средние по секциям и критериям, распределение баллов, средняя сумма каждого эксперта, доклады с наибольшим разбросом) и выгружает CSV. Итоги обновляются раз в минуту. Эксперт на вкладке «Итоги» видит только собственные оценки. В демо-режиме все входят как администратор.
- Статусы: `absent` (доклад не состоялся), `abstain` (эксперт воздерживается, например, как соавтор).

## Сервер (Code.gs)

- `ACCESS_CODE` — код комиссии для экспертов, `ADMIN_CODE` — код администратора (должен отличаться). Код проверяется в каждом запросе, регистр не важен.
- Колонки «Оценки»: Эксперт, ID доклада, Доклад, критерии…, Сумма, Статус, Комментарий, ts, Обновлено. «Сумма» заполняется только у засчитываемой оценки (все критерии, без статуса), поэтому «Сводка» просто усредняет непустые суммы. Сервер пересчитывает сумму сам, клиентскому `total` не доверяет.
- `CRITERIA` **должен совпадать** с `CONFIG.CRITERIA` в index.html по количеству и порядку. Колонки листа вычисляются из этого массива.
- `setup()` запускается вручную один раз: создаёт заголовки и формулу на листе «Сводка». После изменения критериев запустить снова.
- Любая правка Code.gs вступает в силу только после «Управление развертываниями → изменить → Новая версия». URL `/exec` при этом не меняется.

## Развёртывание

1. Google-таблица → Расширения → Apps Script → вставить Code.gs → сменить `ACCESS_CODE` и `ADMIN_CODE` → выполнить `setup` → Развернуть → Веб-приложение (от имени «Я», доступ «Все») → скопировать URL `/exec`.
2. Вставить URL в `CONFIG.SCRIPT_URL` в index.html, закоммитить в `main`.
3. Settings → Pages → Deploy from a branch → `main` / root.

## Проверка

```bash
pip install playwright && playwright install chromium
python tests/smoke.py
```

Тест работает в демо-режиме на временной копии index.html с пустым `SCRIPT_URL`, поэтому его можно запускать и после вставки боевого URL. Он проверяет: ввод оценок, перезагрузку, частичную оценку, статус «не состоялся», двух экспертов, рейтинг, режимы «Секции» и «Статистика» и отсутствие горизонтальной прокрутки при ширине 390 px. Работу с реальным Apps Script тестировать вручную: открыть страницу с двух устройств и посмотреть лист «Оценки».

## Правила при изменениях

- Интерфейс и тексты на русском языке.
- index.html остаётся одним самодостаточным файлом без сборки и внешних зависимостей.
- Mobile-first: кнопки не меньше 44 px, без горизонтальной прокрутки, поддержка тёмной темы через `prefers-color-scheme`.
- Не ломать формат данных в таблице: если там уже есть оценки, колонки не переставлять.
- Код комиссии и URL `/exec` не являются секретом уровня пароля, но в публичных issue и README их не публиковать.
